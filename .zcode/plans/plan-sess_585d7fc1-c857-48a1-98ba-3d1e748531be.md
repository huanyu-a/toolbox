# 友情链接结构化数据表改造

## 目标
友情链接从「整段 HTML 存 KV」改为 **SQLite 数据表管理**（增删改查 + 状态开关），字段在你要求的 url / 网站名称 / 状态 / 编辑 基础上补充：**排序、nofollow 开关、备注**。

## 一、数据表设计（复用现有 SQLite 库 runtime/site_config.db）

```sql
CREATE TABLE IF NOT EXISTS friend_links (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    name       TEXT NOT NULL DEFAULT '',      -- 网站名称
    url        TEXT NOT NULL DEFAULT '',      -- 链接地址
    nofollow   INTEGER NOT NULL DEFAULT 1,    -- 1=输出 rel="nofollow noopener"
    sort       INTEGER NOT NULL DEFAULT 100,  -- 排序，小者在前
    status     INTEGER NOT NULL DEFAULT 1,    -- 1=启用 0=停用（停用不显示但保留数据）
    remark     TEXT NOT NULL DEFAULT '',      -- 备注（内部可见）
    created_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
```

## 二、common.php 改造
1. `site_cfg_pdo()` 中追加建 `friend_links` 表（同一条连接，自动建表逻辑不变）
2. 新增辅助函数：
   - `friend_links_all($onlyActive)` — 按 sort,id 排序查询
   - `friend_links_import_legacy()` — 表为空时自动迁移：解析 config_kv 里的 `friend_links_html`（服务器上已存你恢复的 3 条链接）→ 抓取每个 `<a href>文本</a>` 入库，并记录原链接是否带 nofollow；KV 为空再退回解析默认串。**服务器端零手动操作**
3. 重写 `site_render_friend_links()`：遍历启用行拼接输出（保留现有「友情链接：」前缀 + 竖线分隔 + 首页 only 逻辑不变），对 name/url 做 htmlspecialchars 转义（比之前的裸 HTML 更安全）；url 校验 http/https 协议防止 javascript: 注入
4. 函数名保持不变 → 前台模板 link.html / footer.html / topbar.css 全部无需改动

## 三、后台控制器 Web.php（全部 checkLogin）
- `link()` — 改为**列表页**：表格展示所有行（含停用行）
- 新增 `linkEdit()` — 编辑/新增共用页：GET 回显表单，POST 校验保存（INSERT/UPDATE），成功后 302 回列表
- 新增 `linkDel()` — POST + `form[data-confirm]` 二次确认删除单行
- 通配路由已覆盖新 action，无需动 route/config

## 四、后台视图
- 重写 `web/link.html` — 仿 file/index.html 的 data-table 惯例：标题行含明暗切换按钮、「＋新增链接」按钮、列 = 网站名称 | URL | 排序 | 状态 | 操作(编辑/删除)；删除走 `<form data-confirm="确定删除…">`；页面引入 admin.js
- 新建 `web/link_edit.html` — 表单卡片：网站名称*、URL*（https:// 提示）、nofollow 勾选（默认勾）、排序数字、启用勾选（默认勾）、备注 textarea；保存/取消按钮

## 五、部署验证（tencent 服务器，沿用现有 Docker 流程）
1. tar 同步变更文件到 /www/docker/tools/src/
2. 构建 `cleverest/toolbox:deploy-20260827-dbtbl`（Dockerfile 已含 pdo_sqlite 扩展，无需再改）
3. 容器内 `php -l` 校验全部改动 PHP 文件
4. compose 切镜像重启 → 验证：首页自动迁移出 3 条友链且渲染正确、工具页不显示、后台列表页能打开
5. 本地 commit + push

## 兼容性说明
- 旧 KV `friend_links_html` 仅作一次性导入来源，之后不再读写（数据继续留在库里无害）
- 你在线上后台继续用「新增/编辑」管理条目；排序号越小越靠前
